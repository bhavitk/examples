# multi-nats

One `nats-remote` server, N device `nats-server`s connected to it via leaf
node, all trust (operator/accounts/users) issued with decentralized JWT auth.
See `Plan.md` for the original design brief.

This README covers first-time setup on a fresh machine using the Go tools in
`scripts/setup-operator/` and `scripts/provision-device/`. Both mint NATS
JWTs/creds directly with `github.com/nats-io/jwt/v2` and
`github.com/nats-io/nkeys` - no `nsc` CLI and no extra provisioning Docker
image required. Docker is still used to actually run the NATS servers and
client containers.

## Prerequisites

- **Go 1.21+** - `go version`
- **Docker** and **Docker Compose v2** - `docker version`, `docker compose version`

## 1. Clone and enter the project

```sh
git clone <this-repo>
cd multi-nats
```

## 2. Bootstrap the operator/account trust chain (one time)

Creates the operator, `SYS` account, and `DEVICES` account, writes
`nats-config/resolver.conf` (loaded by `nats-remote`), and mints the
`remote` user's creds that `remote-client` authenticates with.

```sh
cd scripts/setup-operator
go run . -project-dir ../..
cd ../..
```

This writes/overwrites:
- `nats-config/resolver.conf`
- `nsc-data/store/**` (key material - gitignored, never commit it)
- `nsc-data/creds/remote.creds`

Only run this once per environment. Re-running it mints a brand new trust
chain, which invalidates every device's creds minted under the old one -
you'd need to re-provision every device (step 4) afterwards.

## 3. Start the remote side

```sh
docker compose up -d --build nats-remote remote-client
docker logs -f remote-client
```

You should see:
```
[remote] subscribed to device.*.outgoing.data
```

## 4. Provision a device

Mints that device's own JWT/creds (scoped to only its own
`device.<id>.{outgoing,incoming}.data` subjects), writes its
`nats-config/device-<id>.conf` and `docker-compose.<id>.yml`, and brings its
two containers (`nats-<id>`, `device-<id>-client`) up.

```sh
cd scripts/provision-device
go run . -project-dir ../.. a1
cd ../..
```

Repeat for as many device IDs as you want (e.g. `a2`, `a3`, ...). Each is
independent and `nats-remote` is never touched or restarted.

```sh
docker logs -f device-a1-client
```

You should see the device publishing, and `remote-client`'s logs showing it
was discovered and pinged back.

## 5. (Optional) Dashboard

A small web UI that tails every client's logs live and lets you provision
new devices from the browser.

```sh
docker compose up -d --build dashboard
```

Open `http://localhost:8080`.

> Note: the dashboard's "add device" endpoint currently still shells out to
> `scripts/provision-device.sh` (the original shell script), not the Go tool
> above. Both produce the same result, but if you want the dashboard to use
> the Go tool instead, that's a follow-up change, not yet wired up.

## Tearing a device down

```sh
docker compose -f docker-compose.a1.yml down
rm docker-compose.a1.yml nats-config/device-a1.conf nsc-data/creds/a1.creds
```

## Tearing everything down

```sh
docker compose down
rm -f docker-compose.*.yml nats-config/device-*.conf
rm -rf nsc-data
```

## Project layout

| Path | What |
|---|---|
| `docker-compose.yml` | `nats-remote`, `remote-client`, `dashboard` |
| `docker-compose.<id>.yml` | generated per-device override (device's own `nats-server` + client) |
| `nats-config/remote.conf` | `nats-remote`'s static config, includes `resolver.conf` |
| `nats-config/resolver.conf` | generated by `setup-operator` - operator/account JWTs, mem-resolver preload |
| `nats-config/device-<id>.conf` | generated per device by `provision-device` |
| `app/` | the Go NATS client image, used for both `remote-client` and every `device-<id>-client` (`ROLE=remote`\|`device`) |
| `dashboard/` | Go web UI: live log tail + device provisioning button |
| `scripts/setup-operator/` | **Go**, one-time trust chain bootstrap (step 2 above) |
| `scripts/provision-device/` | **Go**, per-device provisioning (step 4 above) |
| `scripts/setup-operator.sh`, `scripts/provision-device.sh` | original shell implementations of the same two tools, kept for reference; both required Docker + an `nsc` CLI image (`provisioning/`) that the Go tools no longer need |
| `nsc-data/` | generated key material and creds - gitignored, machine-local, never commit |

## Troubleshooting

- **`nats-config/resolver.conf not found`** when provisioning a device - run
  step 2 first.
- **`no account jwt found for "DEVICES"`** - same as above; the store under
  `nsc-data/store` doesn't have a trust chain yet.
- **A device's leafnode won't connect / auth errors** - its creds were
  probably minted under a trust chain that setup-operator has since
  regenerated. Re-run `provision-device` for that device ID.
- **`go run .` fails with "cannot find main module"** - run it from inside
  `scripts/setup-operator` or `scripts/provision-device` (each is its own Go
  module), not from the project root.
